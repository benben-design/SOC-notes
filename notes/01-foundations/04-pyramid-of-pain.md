# Pyramid of Pain

`2026-09-08` · 30 דק' · Foundations · [קישור לחדר](https://tryhackme.com/room/pyramidofpainax)

## מה החדר מכסה

- מודל ה-Pyramid of Pain של David J. Bianco: דירוג סוגי אינדיקטורים לפי כמה יקר לתוקף להחליף אותם אחרי שזוהו.
- שש רמות מלמטה למעלה: Hash Values → IP Addresses → Domain Names → Host/Network Artifacts → Tools → TTPs.
- לכל רמה: מה האינדיקטור, איך מזהים אותו, ומה התוקף עושה כדי לעקוף.
- הכלים שמלווים כל רמה: VirusTotal, MetaDefender, any.run, Wireshark/TShark, Snort, YARA, SSDeep, MITRE ATT&CK.

## תובנות מרכזיות

1. ערכו של IOC לא נמדד בכמה קל לזהות אותו אלא בכמה יקר לתוקף להחליף אותו. hash הוא זיהוי מדויק אך חסר ערך מבצעי - שינוי של בית אחד בקובץ מייצר hash אחר לגמרי.
2. האזור הצהוב (host + network artifacts) הוא הנקודה שבה ההגנה מתחילה להשתלם: התוקף כבר לא מחליף שרת אלא צריך לחזור ולשנות את הכלים והשיטות שלו.
3. זיהוי ברמת TTP משאיר לתוקף שתי אפשרויות בלבד - להשקיע מחדש במחקר, אימון וכלים מותאמים, או לוותר ולעבור למטרה אחרת.

## הפירמידה

| רמה | הכאב לתוקף | דוגמאות | זיהוי טיפוסי |
| --- | --- | --- | --- |
| TTPs | Tough | phishing, persistence, lateral movement, exfiltration | מיפוי MITRE ATT&CK, ניטור Windows Event Log |
| Tools | Challenging | maldocs, backdoors, EXE/DLL, password crackers | חתימות AV, כללי YARA, fuzzy hashing |
| Network Artifacts | Annoying | User-Agent חריג, דפוסי URI ב-POST, תעבורת C2 | ניתוח PCAP ב-Wireshark/TShark, התראות IDS |
| Host Artifacts | Annoying | ערכי registry, הרצת תהליכים חריגה, קבצים שהופלו | EDR, ניטור תהליכים, דוחות sandbox |
| Domain Names | Simple | דומייני C2, Punycode, מקצרי כתובות | לוגי proxy, לוגי שרת web, לוגי DNS |
| IP Addresses | Easy | כתובות C2, מקור סריקה | חסימה בפיירוול, deny ברשימות |
| Hash Values | Trivial | MD5 / SHA-1 / SHA-256 של דגימה | lookup ב-VirusTotal / MetaDefender |

## מונחים

<div dir="rtl">

- **Pyramid of Pain** - מודל של David J. Bianco שמדרג סוגי אינדיקטורים לפי מידת ה"כאב" שנגרם לתוקף כשההגנה מזהה וחוסמת אותם.
- **IOC (Indicator of Compromise)** - עצם נצפה שמעיד על פגיעה: hash, כתובת IP, דומיין, מפתח registry, שם קובץ.
- **CTI (Cyber Threat Intelligence)** - מודיעין איומים; איסוף ועיבוד מידע על תוקפים והאינדיקטורים שלהם לצורך זיהוי והגנה.
- **Hash value** - ערך באורך קבוע שמזהה נתונים באופן ייחודי, תוצר של אלגוריתם גיבוב.
- **MD5** - אלגוריתם גיבוב (RFC 1321, Ron Rivest, 1992), פלט 128 ביט. אינו נחשב מאובטח קריפטוגרפית - RFC 6151 מתעד התקפות נגדו, בהן התנגשויות.
- **SHA-1** - אלגוריתם גיבוב (RFC 3174, NSA, 1995), פלט 160 ביט = 40 תווים הקסדצימליים. NIST הוציא אותו משימוש ב-2011 ואסר אותו לחתימות דיגיטליות מסוף 2013 בשל חשיפה ל-brute force.
- **SHA-2 / SHA-256** - משפחת גיבוב של NIST ו-NSA משנת 2001 שנועדה להחליף את SHA-1. SHA-256 מחזיר 256 ביט = 64 תווים הקסדצימליים.
- **Hash collision** - שני קבצים שונים המניבים אותו ערך גיבוב. קיומה שוללת מהאלגוריתם את מעמד ה"מאובטח קריפטוגרפית".
- **VirusTotal / MetaDefender Cloud (OPSWAT)** - שירותי lookup שמחזירים ניתוח קובץ, דומיין או hash מול עשרות מנועי זיהוי.
- **Fast Flux** - טכניקת DNS שבה דומיין אחד ממופה לכתובות IP רבות שמתחלפות בקצב גבוה, דרך hosts שנפרצו ומשמשים proxy. המטרה: להקשות על חסימה ועל איתור התקשורת אל שרת ה-C2.
- **C2 / C&C (Command and Control)** - התשתית שדרכה התוקף שולט בנוזקה שעל המכונה הנגועה ומוציא ממנה מידע.
- **Punycode** - שיטת קידוד שממירה תווי Unicode שאינם ASCII לייצוג ASCII. מנוצלת להתחזות: דומיין שנראה לגיטימי לעין נפתח בפועל ככתובת xn-- אחרת.
- **URL Shortener** - שירות שמייצר קישור קצר שמפנה ליעד. משמש להסתרת דומיין זדוני; הוספת "+" לקישור מציגה את היעד האמיתי. שירותים נפוצים: bit.ly, goo.gl, ow.ly, s.id, smarturl.it, tiny.pl, tinyurl.com, x.co.
- **Any.run** - sandbox מקוון שמריץ דגימה ומציג את התנהגותה בזמן אמת: בקשות HTTP, חיבורים יוצאים, בקשות DNS ותהליכים.
- **Host artifacts** - עקבות שהתוקף משאיר על המכונה: ערכי registry, הרצת תהליכים חריגה, קבצים שהופלו על ידי יישום זדוני, וכל דבר ייחודי לאיום הנוכחי.
- **Network artifacts** - עקבות שהתוקף משאיר ברשת: מחרוזת User-Agent, מידע C2, דפוסי URI בבקשות HTTP POST.
- **User-Agent** - שדה header בבקשת HTTP (מוגדר ב-RFC 2616) שמכיל מידע על הלקוח ששלח את הבקשה. מחרוזת שלא נצפתה בסביבה קודם היא אינדיקטור.
- **PCAP** - קובץ שמכיל dump של חבילות רשת שנלכדו.
- **Wireshark / TShark** - כלי ניתוח תעבורת רשת; TShark הוא גרסת שורת הפקודה שלו, שנוחה לחילוץ שדות מ-PCAP.
- **IDS (Intrusion Detection System)** - מערכת שמנטרת תעבורה או מארח ומתריעה על דפוסים חשודים לפי חתימות או חריגות. דוגמה: Snort.
- **Emotet** - טרויאני נפוץ; בחדר הוא מזוהה דרך מחרוזות User-Agent אופייניות בתעבורה.
- **Maldoc** - מסמך Office זדוני (לרוב מבוסס מאקרו) שמשמש כשלב ראשון בהתקפת spearphishing.
- **Spearphishing** - פישינג ממוקד לאדם או לארגון ספציפי, בניגוד לדיוור המוני.
- **Dropper** - רכיב שתפקידו להוריד ולהתקין את המטען הזדוני בפועל על המכונה.
- **YARA rules** - כללי זיהוי שמאתרים קבצים לפי מחרוזות ודפוסים בינאריים; אחד הנשקים המרכזיים ברמת ה-Tools.
- **Fuzzy hashing** - גיבוב שמאפשר ניתוח דמיון בין קבצים: שני קבצים עם הבדלים קטנים יקבלו ערכים קרובים, כך שאפשר לזהות וריאנט של אותו כלי גם אחרי שינוי. המימוש המוכר הוא SSDeep, ותוצאותיו מוצגות גם ב-VirusTotal.
- **MalwareBazaar / Malshare** - מאגרים ציבוריים של דגימות נוזקה ופידים זדוניים, שימושיים ל-threat hunting ולתגובה לאירועים.
- **SOC Prime Threat Detection Marketplace** - פלטפורמה שבה אנשי אבטחה משתפים כללי זיהוי לאיומים, כולל CVE-ים שמנוצלים בפועל.
- **TTPs (Tactics, Techniques & Procedures)** - כלל השלבים שהתוקף נוקט מהחדירה ועד השגת המטרה: טקטיקה היא ה"למה", טכניקה היא ה"איך", ופרוצדורה היא המימוש הספציפי.
- **MITRE ATT&CK** - מטריצה שממפה את הטקטיקות והטכניקות הידועות של תוקפים, ומשמשת שפה משותפת לתיאור TTPs.
- **Pass-the-Hash** - טכניקה שבה התוקף מתאמת מול שירות באמצעות ה-hash של הסיסמה במקום הסיסמה עצמה. ניתן לזהות דרך ניטור Windows Event Log.
- **Lateral movement** - התקדמות התוקף בין מכונות ברשת אחרי השגת דריסת רגל ראשונית.
- **Data exfiltration** - הוצאת מידע מהארגון אל התוקף; קטגוריה נפרדת במטריצת ATT&CK.
- **APT (Advanced Persistent Threat)** - קבוצת תקיפה מתוחכמת ומתמשכת, לרוב עם חסות מדינתית ומטרות ארוכות טווח.

## מה למדתי

למדתי על כל רמות האינדקציות שיש על התוקף מבחינת הקודי שיהיה עליו לעבוד בשביל לייצר שיטות חדשות, ניתן להבין ולמצוא את האינדיקציות בעזרת כלים רבים מסוגים שונים. 

## איפה נתקעתי

נתקעתי בעיקר בחלק של הTTP היה לא פשוט בשאלה האחרונה באמת למצוא את השם השיטה הספציפית שבה השתמשו קבוצת ההאקרים הסינית.

## זווית לראיון

אם שואלים "מה עושים עם IOC שקיבלת מפיד מודיעין" - התשובה היא לא רק לחסום אותו, אלא לדעת לאן הוא נופל בפירמידה: hash או IP נחסמים בעלות אפסית לתוקף, ולכן שווה להשקיע את הזמן בשאלה איזו התנהגות (artifact או TTP) עומדת מאחוריהם ואפשר לבנות עליה כלל זיהוי עמיד.
